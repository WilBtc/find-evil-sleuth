# find-evil-sleuth — Design Context

## Users

**Primary**: SANS DFIR (Digital Forensics & Incident Response) judges evaluating
hackathon submissions. Veteran practitioners. They've watched countless
submissions and can detect cargo-cult forensics from across a room. They
respect:
- Real evidence handling, not theatre.
- Audit trails over dashboards.
- Defaults that don't hide their reasoning.
- Tools that respect their expertise rather than narrating it back to them.

**Secondary**: Other DFIR practitioners and SecOps engineers who'd run this
against real cases on a SIFT workstation.

## Use cases

1. Watch a 5-minute terminal-only demo video, then click into the live
   inspector to verify the audit story is real, not a rendered slide.
2. Drill from any narrator-cited `[F-NNN]` to the exact tool_call, blake3
   hash, and stdout slice that produced it.
3. Run their own SQL against the audit substrate (read-only) without
   leaving the page.
4. Inspect the AGE attack graph and the Merkle audit chain.

## Brand personality

- **Trustworthy and earned.** This is forensic software; gravitas matters.
  No mascots, no emoji, no jokes.
- **Quiet expertise.** The judges are the experts; the interface assists,
  it doesn't lecture.
- **Editorial, not operational.** Reads like a well-edited magazine spread,
  not a Datadog dashboard.

## Aesthetic direction — "Claude.ai applied to forensics"

- **Warm cream/off-white** background, not dark mode. Off-the-shelf SecOps
  dashboards are dark with neon accents; we go the opposite direction.
  Confidence over cool.
- **Clay/orange accents** (Claude's signature warm hue, OKLCH around
  `oklch(72% 0.13 50)`) used SPARSELY for primary actions and key signals.
- **Tinted neutrals** — never pure gray, never pure white. Backgrounds and
  text both warm-toned.
- **Generous whitespace.** Editorial rhythm. Asymmetric where it earns its
  place; never centered-everything.
- **Typography**: a refined serif for display + a clean humanist sans for
  body (e.g. Source Serif 4 + Inter Tight or similar; loaded via CDN with
  `font-display: swap`). Mono ONLY for hashes, UUIDs, MITRE codes,
  filesystem paths.
- **Semantic color**: emerald (`confirmed`), rose (`refuted`), amber
  (`partial` / `inconclusive`). Used as small chips, not large fills.
- **No glassmorphism, no gradients on metrics, no neon, no gradient text.**

## Design principles

1. **Show the substrate.** Where possible, surface real DB shapes (counts,
   timestamps, blake3 hashes) rather than pre-digested summaries. Judges
   want to inspect.
2. **One primary action per screen.** No competing CTAs.
3. **Progressive disclosure.** Start with a clean surface; let drill-downs
   reveal density.
4. **Rhythmic spacing.** Tight (8–12 px) inside groups, generous (48–96 px)
   between sections. Never identical.
5. **No template stamps.** No icon-above-heading rows, no equal-card grids,
   no big-number-with-tiny-label hero metric.
6. **Pass the AI-slop test.** A judge should ask "who designed this?", not
   "which AI made this?"

## Constraints

- Stack is locked: **Tera templates + HTMX 2 + Tailwind (prebuilt static
  CSS, no node toolchain)**. No React, no Vue, no Svelte.
- All data is read directly from Postgres via the existing axum routes.
- Local-only deployment via `./scripts/saas.sh up`. No public hosting.
- WCAG AA contrast minimum throughout.
